# Baseline Capability Catalogue

## Contract used by every capability

Each capability is a deterministic operation registered by stable identifier and version. It declares accepted input schemas, emitted output schemas, prerequisites, domain-rule dependencies, resource accounting and deterministic settings. Every output cites immutable evidence references and the operation/version/configuration that produced it. An operation may produce leads or proposed findings; it cannot accept its own finding.

Authority is layered:

- the retrieval service decides whether a source and scope are authorised;
- an approved, effective-dated domain package supplies business meaning and thresholds;
- the operation performs only its declared transformation;
- evidence-sufficiency rules decide whether a claim is eligible for proposal;
- an independent verifier accepts, rejects or leaves the claim unresolved; and
- a report projector renders verified state without changing it.

`General method` below means reusable mathematics or evidence handling. `Domain rule` means approved business semantics such as an SLA clock, source precedence or KPI population. Implementations must not embed domain rules inside general methods.

## Baseline acceptance profile

Before Path A is eligible for controlled comparison, every applicable capability must pass schema conformance, deterministic replay, evidence-lineage, permission-denial, partial/failure, budget and synthetic semantic fixtures. Required scenario categories must exercise multi-round discovery, missing evidence, contradictions, ambiguous identity, material qualification, invalid references and tool failure. Numerical performance thresholds remain **Requires confirmation** until preregistered under B01. Passing contract tests would establish implementation conformance only; it would not establish business-rule approval, Windows/live-source behaviour or investigative performance.
